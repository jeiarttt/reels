# 귀여운 릴스 카드뉴스 만들기

기본 스킬 `reels-card-news`(저장소의 `skill/`)는 그대로 두고, **표현 방식만 귀엽게** 바꾼 별도 스킬이다. 이 스킬의 파일은 `skill-cute/`에만 둔다. 기본 스킬의 파일은 수정하지 않는다.

## 최우선 원칙 (기본 스킬과 동일, 귀엽다고 느슨해지지 않는다)
`skill/SKILL.md`의 "최우선 원칙"과 `skill/references/facts.md`(사실 확인·면책·검수)를 **그대로** 따른다.
- 모든 내용은 제작 당일 기준, 거짓·미확인 수치 금지, 공식 출처 확인 여부를 솔직히 보고, 검수 생략 금지.
- 후킹이 약속한 내용이 본문에 없으면 만들지 않는다.
- 귀여운 말투와 스티커는 **정보를 가리거나 과장하지 않는 선**에서만 쓴다. 보장·압박 표현("무조건", "100%", "안 하면 손해")은 귀여운 말투로 바꿔도 금지다.

## 이 스킬의 핵심 3가지
1. **첫 컷이 가장 중요하다.** 릴스는 1초 안에 더 볼지 정해진다. 표지는 2줄, 18자 이내로 "무엇이/언제/왜 지금"이 한눈에 들어오게 쓰고 가장 크게 만든다.
2. **컷당 글자는 최소로.** 한 컷에 메시지 하나, 문구는 16자 이내(공백 제외), 핵심만 강조(전체 3곳 이내).
3. **스티커는 아껴서, 필요하거나 강조할 곳에만.** 영상 전체 최대 3개(표지 + 주의·강조 컷 + 마지막 화면 정도), 같은 스티커 반복 금지.

## 작업 순서
1. 주제·핵심 메시지 한 줄·대상 파악 → 기본 스킬 순서 3(사실 확인)·4(후킹-본문 일치)를 똑같이 한다.
2. **컷을 먼저 줄인다**: 정보를 컷으로 나누고, 컷마다 "이 컷의 단 하나의 메시지"만 남긴다. 나머지는 캡션으로 보낸다. (`references/cute-writing.md`)
3. 스티커를 놓을 곳을 정한다: 표지, 그리고 사람이 놓치면 안 되는 곳(마감·주의). (`references/stickers.md`)
4. `data/script.cute.json`에 대본을 쓴다(`"theme": "cute"`). 형식은 기본 스킬 `references/schema.md` + 아래 추가 항목.
5. `npm run validate -- data/script.cute.json`으로 검사(귀여운 테마 전용 경고 포함).
6. 정지 화면으로 표지·말풍선·카드·체크 메모·마지막 화면을 확인한다.
7. `npm run render:job -- <id> --force --script=data/script.cute.json`
8. 렌더 후 화면 검수와 내용 검수를 하고 결과를 보고한다.
9. 귀여운 버전 전용 Notion DB에 완료 처리(`references/notion.md`). **기본 버전 DB에는 쓰지 않는다.**

## 대본 JSON 추가 항목 (기본 포맷에 더해)
- `theme`: "cute" (필수)
- `hookSec`(기본 3), `ctaSec`(기본 3.5): 표지·마지막 화면 길이(초). 일반 컷은 `t` 3~4.5초. **전체 20~25초.**
- `hookSticker`, `hookSfx`, `ctaSticker`, `ctaSfx`: 표지·마지막 화면의 스티커 파일 이름(확장자 제외)과 의성어 태그
- 컷(`scenes[]`)의 `sticker`, `sfx`: **강조할 컷에만** 넣는다
- 카드의 `emoji`: 카드 아이콘(숫자·기간·금액에 어울리는 이모지)
- `accentColor`: 파란색 `#2457F5`

## 상세 문서
| 언제 | 읽을 파일 |
|---|---|
| 문구·말투·컷 구성 | `references/cute-writing.md` |
| 레이아웃·색·폰트·여백 | `references/cute-design.md` |
| 스티커를 고르고 쓰고 만들 때 | `references/stickers.md` |
| 렌더 후 Notion 완료 처리 | `references/notion.md` |
| 깃 작업 규칙 | `references/git.md` |

사실 확인·면책·게시 전 검수는 기본 스킬의 `skill/references/facts.md`를 읽는다.
