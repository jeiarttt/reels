# 릴스 카드뉴스 대본 만들기

주제가 무엇이든 같은 포맷과 같은 말투로 대본을 만든다. 주제별 내용은 매번 새로 받고, 계정 정보는 아래 "계정 프로필"을 따른다.

## 작업 순서
1. 주제, 핵심 메시지 한 줄, 대상(누구에게 도움이 되는가)을 파악한다.
2. 주제 유형을 고른다(아래 "장면 구성 패턴").
3. 사실 확인이 필요한 주제(정책, 금액, 날짜, 법규, 가격, 통계, 제품 사양)는 웹 검색으로 확인한다.
   - 공식 출처 우선, 한 곳에서만 나온 내용은 "미확인"으로 표시하고 영상에서는 뺀다.
   - 서로 다른 제도·제품·기관을 섞지 않는다. 출처가 엇갈리면 영상에서 뺀다.
   - 연도와 시점 상태(공고 전 / 진행 중 / 종료)를 먼저 판단해 각도를 정한다.
4. JSON 포맷으로 대본을 만든다.
5. `verify_before_post`로 게시 전에 사람이 확인할 항목을 낸다.

## 장면 구성 패턴
- 정보·혜택형: 후킹 → 핵심 조건 3~4개 → 신청·확인 방법 → CTA
- 팁 모음형: 후킹 → 팁 3~5개(장면당 하나) → 한 줄 정리 → CTA
- 비교형: 후킹 → A 특징 → B 특징 → 어떤 사람에게 맞는지 → CTA
- 방법·절차형: 후킹 → 단계별 한 장면씩 → 자주 하는 실수 → CTA
- 경험담형: 후킹(결과 먼저) → 상황 → 한 일 → 결과·배운 점 → CTA

## 대본 JSON 포맷
- `id`, `mode`: "card_news"
- `style`: "photo"(사진·영상 배경, 모든 장면 가운데 정렬) 또는 생략(네이비 카드)
- `backgroundSrc`: 사용자가 준 이미지·영상으로 **전체 배경을 덮어쓸 때만** 채운다. public/user/ 에 넣고 "user/파일명". 비워두면 장면별 `bg`(스톡)를 쓴다
- `hookLabel`(선택), `hook`, `hookBg`: 첫 화면(3.5초)
- `scenes[]`: `{ t(초), kind, label(선택), bg, ... }` 5~6개, 장면당 4~7초
  - `kind: "text"`(기본): `text`
  - `kind: "cards"`: 요약 카드 `cards: [{ big, small }]` 3~4개 (핵심 숫자·기간·금액)
  - `kind: "table"`: 비교표 `table: { head: [...], rows: [[...]] }` 열 2~3개, 행 3~4개
  - `bg: { src, type?, startFrom? }`: 장면 배경. src는 public/ 기준(`stock/…`, `user/…`). mp4/mov/webm은 영상, 그 외는 이미지
- `ctaLabel`(선택), `cta`, `ctaBg`: 마지막 화면(4초)
- `accentColor`: 포인트 컬러(기본 #FF8A1F)
- `status`: "pending"(확정 전) 또는 "confirmed". confirmed가 아니면 `disclaimer_overlay` 문구가 영상 하단에 자동 표시된다
- `disclaimer_overlay`, `caption`, `hashtags`, `sources`, `verify_before_post`

## 배경 사진·영상 규칙
- 기본 배경은 주제와 관련된 **실사 사진·영상**이다. 일러스트·벡터·AI풍 그림은 쓰지 않는다.
- 무료 상업 이용 가능한 출처(Pexels, Unsplash)만 쓴다. 사진 속 **상호·브랜드 간판, 사람 얼굴이 크게 나온 컷, 로고**는 피한다.
- 기본은 **날씨 좋은 낮에 찍은 맑은 사진**(밤·야경·흐린 날 제외). 사용자가 따로 말하면 그에 따른다.
- 사진은 세로 릴스에 크게 확대돼도 깨지지 않게 폭 1600px 이상, 영상은 1080p 이상을 고른다. 파일은 `public/stock/` 에 의미 있는 이름으로 저장한다(예: seoul-dusk.jpg).
- 한 영상에서 같은 사진을 3번 이상 쓰지 않는다. 첫 화면은 움직이는 영상이면 좋다.
- 글자가 잘 읽히도록 어두운 오버레이를 자동으로 얹는다(낮 사진 기준 텍스트 장면 약 0.22, 카드·표 장면 약 0.32, 첫 화면 약 0.18. 사진이 회색빛으로 죽어 보이면 더 낮춘다). 사진이 너무 어둡게 보이면 오버레이를 낮추고 더 밝은 사진을 고른다.
- **사용자가 영상·이미지를 주면** 그 파일을 `public/user/`에 넣고, 전체를 바꾸려면 `backgroundSrc`, 장면별로 바꾸려면 해당 장면 `bg.src`를 "user/파일명"으로 지정한다. 사용자 파일이 스톡보다 항상 우선한다.

## 폰트 규칙
- **큰 제목(첫 화면 `hook`, 마지막 화면 `cta`)은 히피체**, **본문·라벨·카드·표·면책 문구 같은 내용과 작은 정보성 글은 Pretendard**로 쓴다.
- 히피체 제목은 자간 -1%(`letter-spacing: -0.01em`)를 적용한다. 히피체는 굵기가 하나(400)뿐이라, 굵게 보이도록 같은 색 외곽선(`-webkit-text-stroke: 0.035em currentColor`)을 얹는다. 제목 크기는 첫 화면 116px, 마지막 화면 102px. Pretendard는 400/700/800/900을 쓴다.
- 폰트 파일은 `public/fonts/`에 둔다.
  - 히피체: `hippie.woff2` — `@font-face { font-family: 'Hippie'; src: url('https://cdn.jsdelivr.net/gh/Project-Noonnu/2610081905@hippie/hippie/hippie_히피체.woff2') format('woff2'); font-weight: 400; }` 에서 받은 파일 (주소의 한글은 `%ED%9E%88%ED%94%BC%EC%B2%B4`로 인코딩해서 받는다)
  - Pretendard: npm `pretendard` 패키지의 `dist/web/static/woff2/Pretendard-{Regular,Bold,ExtraBold,Black}.woff2`
- 라이선스: 히피체는 SIL OFL 1.1(눈누 안내 기준 개인·상업 이용 무료, © AI올컷), Pretendard는 SIL OFL 1.1. 영상에 쓰는 것은 문제없지만 **폰트 파일을 저장소·배포물에 포함할 때는 저작권 고지와 라이선스를 함께 둔다**(`public/fonts/*-LICENSE.txt`). 폰트 파일 단독 판매·본인 제작처럼 재배포는 금지.
- 장면 본문 큰 글씨(`text`)는 Pretendard ExtraBold(800). 히피체로 바꾸고 싶은 제목이 있으면 사용자에게 먼저 확인한다.

## 세로 위치
- 모든 장면의 내용 블록은 화면 정중앙보다 **약 70px 위**에 둔다(하단 `padding-bottom: 140px`). 하단 면책 문구·플랫폼 UI와 겹치지 않게 하기 위해서다.

## 장면 유형 고르기
- 숫자·기간·금액 같은 핵심 수치가 3개 이상이면 `cards`로 보여준다.
- 연도·조건·제도를 나란히 비교하면 `table`로 보여준다. 값이 확정되지 않았으면 셀에 "미공고"처럼 쓴다.
- 나머지는 `text`. 영상 하나에 text만 이어붙이지 말고, 내용에 맞으면 cards 또는 table을 1~2장면 넣는다.
- 카드는 불투명한 흰색 배경에 큰 숫자는 포인트 컬러, 설명은 짙은 남색이다. 카드의 `big`은 짧게(한 줄, 10자 안팎), `small`은 설명 한 줄. 표 셀은 한 칸 2줄 이내(`\n` 가능).

## 텍스트 효과·줄바꿈 규칙
- 글자는 **단어 단위로 아래에서 살짝 올라오며 페이드인**한다(간격 약 0.1초, 이동 20px 안팎). 흔들림·회전·확대 같은 과한 효과는 쓰지 않는다.
- 카드는 하나씩 위로 떠오르듯, 표는 머리글 → 행 순서로 등장한다. 장면 끝에는 짧게 페이드아웃.
- 줄바꿈은 **단어(띄어쓰기) 단위**로만 한다. 한 단어를 글자 중간에서 끊지 않는다(`word-break: keep-all`). 조사가 붙은 덩어리("[[20만 원]]을")도 끊지 않는다.
- 의미 단위로 `\n`을 직접 넣어 한 줄 길이를 고르게 맞춘다(한 줄 12~14자 안팎).

## 글쓰기 규칙
- 말투는 "~해요/~예요" 체. 말 걸듯이 친근하게, 반말과 과한 감탄은 쓰지 않는다.
- 첫 화면은 결과나 궁금증이 바로 보이게 쓴다. 한 줄 짧게, 최대 2줄.
- 한 장면에 하나의 메시지, 최대 3~4줄. 줄바꿈은 `\n`.
- 라벨은 글만 봐서 맥락이 안 잡힐 때만 넣고, 문구만으로 충분하면 뺀다.
- `[[ ]]`로 핵심 숫자·단어만 포인트 컬러로 강조한다. 전체에서 2~3곳 이내.
- 캡션은 계정 시점의 한 줄 + 기준 시점 문구(해당할 때).
- 이모지는 첫 화면과 캡션에서만 가볍게 쓴다.

## 면책 규칙
- 시점이 바뀔 수 있는 정보(정책, 가격, 일정, 조건)는 `disclaimer_overlay`("○○년 기준 · 변경될 수 있어요")를 넣고 `status`를 "pending"으로 둔다.
- 공식 출처로 확인한 뒤에만 사람이 `status`를 "confirmed"로 바꾼다.
- 시간이 지나도 변하지 않는 팁은 `disclaimer_overlay`를 생략한다.

## 게시 전 검수 체크리스트
- 수치, 날짜, 조건이 공식 출처와 일치하는가
- 기관·제품·제도 이름이 맞는가
- 기준 연도와 시점 표기가 맞는가
- 저작권이 있는 이미지·음원·폰트를 쓰지 않았는가 (스톡은 Pexels/Unsplash 라이선스 확인, 간판·브랜드 노출 확인, 폰트 라이선스 고지 파일 동봉)
- 배경 위에서 글자가 충분히 읽히는가, 카드·표 글자가 잘리지 않는가
- 과장된 표현, 보장하는 말투("무조건", "100%")를 쓰지 않았는가

## 레퍼런스 활용 규칙
- 레퍼런스(남의 릴스·쇼츠·글)는 주제 발굴과 구성 패턴 분석용으로만 쓴다.
- 문구, 장면 순서, 영상, 이미지를 그대로 따라 하지 않는다. 우리 계정 시점으로 새로 쓴다.
- 레퍼런스에서 가져온 수치·사실은 반드시 공식 출처로 다시 확인한다.

## 계정 프로필 (계정 바뀌면 이 부분만 수정)
- 정체성: 부산 출신으로 서울에 상경해 사는 2030 갓생러
- 채널 주제: 재테크, 자취 꿀팁, 청년 혜택
- 해시태그 기본: #자취꿀팁 #2030재테크 #상경러 (주제에 맞게 추가)
- 캡션 마무리 톤: 같은 상경러 입장의 한마디
